# Multiverse Markets: frontend

Landing page and wallet sign-in for Multiverse Markets, which turns Farcaster arguments
into prediction markets on Uniswap V4, resolved by Chainlink CRE.

Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS 4, GSAP + Lenis for scroll
motion, and Privy + wagmi for sign-in and wallets on Arbitrum Sepolia, where the
contracts are deployed.

## Getting started

```bash
npm install
cp .env.example .env.local   # then fill in NEXT_PUBLIC_PRIVY_APP_ID
npm run dev                  # http://localhost:3000
```

Without a Privy app id the site still runs; sign-in is shown as unavailable.

### Privy dashboard

In [dashboard.privy.io](https://dashboard.privy.io), for the app whose id is in `.env.local`:

- **User management → Authentication:** enable the login methods you want (email,
  wallet, Google, Farcaster). The sign-in modal shows exactly what is enabled there.
- **App settings → Domains:** add `http://localhost:3000`, the deployed URL, and
  `https://farcaster.xyz` for the Farcaster mini-app.

The **App secret** is for servers only. Never put it in a `NEXT_PUBLIC_` variable.

## Contracts

The app talks to the `MarketplaceFactory` at `NEXT_PUBLIC_MARKETPLACE_FACTORY_ADDRESS`.
Its ABI is generated by the [wagmi CLI](https://wagmi.sh/cli) from the Foundry project
and committed as `src/lib/contracts/generated.ts`, so building the app doesn't need
Foundry. After changing a contract, run `npm run generate` (this compiles `../contracts`,
whose dependencies must be installed in `contracts/lib`) and commit the result.

Market code lives in `src/lib/markets/`:

- `reads.ts` and `writes.ts`: plain async functions over a wagmi config. Writes simulate
  first, so a revert is reported with its reason before the wallet opens.
- `hooks.ts`: React hooks over them: `useMarkets`, `useMarket`, `usePosition` and
  `useCreateMarket`, `usePlaceBet`, `useProposeOutcome`, `useDisputeOutcome`, `useRedeem`.
- `market.ts`: types and pure helpers (outcomes, status, odds, bet quotes, redeem amounts).

`scripts/verify-quotes-on-fork.mts` checks those quotes against the real contract on a local
fork (instructions in its header); run it whenever the contract's bet or redeem logic changes.

Show any failure with `getErrorMessage` from `src/lib/contracts/errors.ts`, which turns
contract errors and wallet rejections into short messages.

## Layout

```
src/
  app/              root layout (fonts, providers, navbar), global styles, favicon
    (landing)/      home page; its layout adds the site footer
    markets/        /markets (app pages have no footer)
  components/       page sections (Hero, Explore, HowItWorks, Benefits, Faq, Footer)
    markets/        market list, market tile, odds bar
      detail/       the /markets/[id] page: odds, bet panel, propose / dispute / redeem, progress
    wallet/         Privy/wagmi providers, sign-in button, account menu, mini-app login
  lib/              chain, wagmi and Privy config, GSAP/Lenis setup, shared hooks, demo data
    contracts/      generated ABI, factory address and config, error messages
    markets/        market reads, writes, hooks and helpers
public/             benefit tile artwork, standalone logo
```

## Notes

- Fonts load through `next/font/google`, so the build fetches them from Google Fonts.
  Offline, Next.js falls back to system fonts and logs a warning.
- `next.config.ts` turns off Turbopack's on-disk caches, which have served stale CSS
  in development.
- Market data on the page (hero timeline, market card, phone screens) is demo content
  until markets are read from the contracts.
